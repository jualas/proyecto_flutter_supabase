Diap. 2: El Problema y Origen
Origen personal
La idea surgió de mi experiencia: me dieron el modelo de anteproyecto en Google Drive, tuve que convertirlo a PDF y devolverlo. Este proceso manual me hizo plantearme crear un software que gestionara esto de forma eficiente.
Evolución
Fui añadiendo funcionalidades según identificaba necesidades. El proyecto creció hasta incluir: comunicación integrada, gestión de proyectos, tableros Kanban y sistema de roles.

Problema general: Proceso basado en documentos Office → PDF → imprimir → firmar. Genera burocracia, lentitud y falta de trazabilidad.

Diap. 3: La Solución

Concepto: Software que digitaliza todo el ciclo del anteproyecto.

  • Ciclo de Vida Digital: Gestión 100% digital
  • Gestión por Roles: Interfaces específicas para cada usuario
  • Tecnología Moderna: Stack actual y escalable
Diap. 4: Funcionalidades Clave
  • Gestión de Anteproyectos: Creación, envío y revisión digital
  • Tablero Kanban: Solo disponible cuando el anteproyecto está aprobado y existe proyecto. Checklist de logros, opaco al tutor.
  • Comunicación Integrada: Canal directo alumno-tutor

Diap. 9: Base de Datos y Seguridad
Qué decir
"La base de datos tiene 26 tablas que almacenan toda la información: usuarios, anteproyectos, proyectos, tareas, mensajes... El diseño fue iterativo, creando tablas según las necesitaba."
Sobre RLS
"PostgreSQL incluye un sistema de seguridad llamado RLS que protege los datos en la base de datos. Cada estudiante solo ve sus proyectos, cada tutor solo sus alumnos. Es una capa de seguridad independiente de la aplicación."
Si preguntan más:
"El diseño fue evolucionando. Las tablas principales son usuarios, anteproyectos, proyectos y tareas. La seguridad RLS viene incluida en Supabase."
Diap. 10: Organización del Código (BLoC)
Qué decir
"Seguí el patrón BLoC, similar al MVC del ciclo. La idea es la misma: separar lo que ve el usuario de la lógica que procesa los datos."

! Notas para la Defensa

1. Digitalización del Anteproyecto
Enfatizar que solucionamos la forma de presentar el anteproyecto (primera fase para que el tutor valide).
2. Tareas como Checklist
Las tareas son un guion de trabajo para marcar logros. La parte de proyecto es opaca al tutor; el alumno es autónomo.
3. Multiplataforma
Aclarar: NO trabajamos con iOS, sí con Web, Windows y Android.
4. Autenticación Limitada
El acceso está limitado a un dominio concreto (centro educativo), no es aplicación abierta.
5. Si preguntan técnico
  • BD: "26 tablas, diseño iterativo, RLS incluido en Supabase"
  • Código: "Patrón BLoC, similar a MVC: separar pantallas, lógica y datos"
